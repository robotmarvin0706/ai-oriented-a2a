## Implementation notes

Choices the pre-registration leaves open, fixed in code before the main run (none changes a rule):

1. Bootstrap: §12 asks for a percentile bootstrap stratified by seed and seeded with `stable_int("selection-bootstrap", host, contrast)`. `timeout_recovery.run.bootstrap_ci` is not stratified and uses another seed prefix, so `analysis.stratified_bootstrap` implements §12 with the same B (`BOOTSTRAP_B` = 2000) and the same percentile indices. `summarize_arm` is per case and is not used; the run-level summaries are in `analysis.arm_summary`. `Host`, its gate, `RuleStrategyModel`, `run_window`, `working_policy` and `stable_int` are reused unchanged.
2. Task t of a run is `Case(stable_int("selection", seed, run), t)`; its 3 `immediate` + 3 `delayed` episodes give the task SR. At a slot the gate's isolation runs on the slot task's case against the current policy.
3. Prior receivers (§6.2): receiver j of packet p is `Case(stable_int("prior", seed, run, p, j), 0)` for j = 0..m-1, a fresh `naive_host` that receives the packet through `Host.handle_message`. m and the phi = 0.15 flips come from `stable_int("prior-noise", seed, run, p)`.
4. Honest `verification_claim.value` (§6.2): the mean SR (6 episodes per case) of the policy the packet states, applied to a `naive_host` start policy, over 30 further prior-stream cases j = 1000..1029; `repro.seed` is the registered seed. The dishonest peer (§6.3) draws from `stable_int("dishonest", seed, run, p)` and runs nothing.
5. Pool (§6.1): drawn from `stable_int("pool", seed, run)`; packet ids are opaque hashes that reveal neither peer nor family; every packet has `type = failure_mode` and `absorption.method = prompt_injection`. Ground truth (family, author) is kept beside the packet and follows the content under the V2 shuffle.
6. Own Absorption Results (§7.2): status `absorbed` counts as `own_absorbed`; every other status counts as `own_not_absorbed` (in this host a gated-out change is reported as `rejected` after its rollback). A result is attributed to the `provenance.source_ref` of the packet as delivered (shuffled in V2) only when its `packet_ref` equals the packet id.
7. `claim_selection` (§7.3): ties in `value` and the order of ineligible packets use the tie RNG `stable_int("tie", seed, run, slot)`; in this pool every packet is eligible.
8. Tokens: task tokens are the six evaluation episodes, including the resident absorbed context, as in `host.py`. Slot tokens are the absorption block (or file text for B) plus both isolation windows plus the post-rollback replay. Selection reading (§7.4) is the sum of `approx_tokens` of each untried packet's envelope (every field except `content`) at each slot, for D1, D2 and V2 only.
9. V1 and V2 are registered on the primary contrast on `naive_host` (§11); their outcomes gate every table, including the secondary tables on `working_host`. V1/V2 computed on `working_host` are reported as information only.
10. "CI inside [-delta, +delta]" (R2, V2) is inclusive at the bounds. All rule comparisons use exact rational arithmetic on success counts.
11. Attribution rate: a policy change is traceable when an Absorption Result with `status = absorbed` and `packet_ref` equal to the delivered packet id exists. B has no packet id and no Absorption Result, so its rate is 0 by construction.
12. Pilot (§13): with 50 tasks only slots T1 and T26 exist, and the plateau window is the last 50 tasks, i.e. the whole pilot. The pilot is a pipeline check only.
13. Run log: after the pilot, the main run was executed once to `/tmp` and then regenerated into the committed files. Between the two, only report formatting changed (B − A is shown as information because the §12 labels are worded for selection contrasts; `runs.jsonl` was made compact). No simulation, selection, endpoint or rule code changed, and every number is identical.

## Wording (§14)

`plateau_SR` is the mean task SR over T151–T200. `D1 − C` is the increment from using envelope fields to select packets under this scenario. An R2 result reads `equivalent within ±0.10 ΔSR`; R4 reads `undetermined`. Only an R1a result may be stated as support for the envelope. The attribution rate is a process metric.
