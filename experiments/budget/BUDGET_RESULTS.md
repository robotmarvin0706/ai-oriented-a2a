## Scope and caveats

- The fast-path rule of §6 is a single-project, non-normative receiver rule over the v0.4 `verification_claim` fields; it is not part of `SPEC.md` and no other project is bound by it.
- `impls/go/` reads `verification_claim.repro.n` only for the experiment 1 `claim_selection` ranking; it does not use `verification_claim.repro` for gate skipping or for any absorption decision.
- Scope: one simulated tool (`web_search` timeout recovery) with a rule-parser receiver (`deterministic-rule-host-v1`), synthetic peers and forged claims generated by this experiment -- not an LLM receiver and not a real API.
- A realised half-width of the token contrast above 0.039 means the run was noisier than the §10 plan; the point estimate is then read as less precise, not as a different verdict.
- Honest matching claims measure 74-75 tokens per read in this run's claim accounting (prereg planning value about 71); the measured mean is what is reported, and no planning value is changed.
